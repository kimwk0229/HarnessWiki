# HarnessWiki 스키마 (Schema Definition)

HarnessWiki의 데이터 구조, 파일 포맷, 메타데이터 명세를 정의합니다.

---

## 1. 파일 구조

```
HarnessWiki/
├── raw/                          # 원본 자료 (원본 무결성, write-once)
│   └── YYYY-MM-DD_슬러그/
│       ├── raw.md                # 회의 원문 (수정 금지)
│       └── meta.md               # 메타카드 (제목/일시/참석자/요약)
│
├── wiki/                          # 주제 페이지 (누적·합성)
│   ├── topics/
│   │   └── 슬러그/
│   │       └── 슬러그.md          # 폴더 노트 형식
│   ├── 결정/
│   │   └── 결정.md                # 결정사항 롤업
│   ├── 액션아이템/
│   │   └── 액션아이템.md          # 액션아이템 롤업
│   ├── 보류/
│   │   └── 보류.md                # 보류 항목 추적
│   └── 사람/
│       └── 사람.md                # 팀 멤버 및 역할
│
├── schema/
│   └── SCHEMA.md                  # 이 파일
│
├── handover/                      # 작업 히스토리
│   └── NN_제목.md
│
├── index.md                       # 위키 카탈로그
├── log.md                         # 시간순 변경 이력
├── CLAUDE.md                      # 규칙 정의
└── README.md
```

## 2. 파일 명명 규칙

### 2.1 원본 폴더 (`raw/YYYY-MM-DD_슬러그/`)

| 항목 | 규칙 | 예시 |
|---|---|---|
| **폴더명** | `YYYY-MM-DD_슬러그` | `2026-08-10_결제연동회의` |
| **날짜** | ISO 8601 (YYYY-MM-DD) | `2026-08-10` |
| **슬러그** | 소문자, kebab-case | `온보딩-개선`, `제품주간회의` |
| **중복 처리** | 같은 날 여러 회의는 접미사 | `2026-08-10_회의-오전`, `회의-오후` |
| **파일명** | 고정 | `raw.md`, `meta.md` |

### 2.2 주제 페이지 (`wiki/topics/슬러그/슬러그.md`)

| 항목 | 규칙 | 예시 |
|---|---|---|
| **폴더명** | 슬러그 (kebab-case) | `결제-연동`, `온보딩-개선` |
| **파일명** | 폴더명과 동일 (폴더 노트) | `결제-연동.md` |
| **구조** | 단일 md 파일 (1폴더 = 1파일) | ✅ |

## 3. 메타데이터 스키마

### 3.1 원본 메타카드 (`raw/YYYY-MM-DD_슬러그/meta.md`)

```markdown
---
title: {string}          # 필수: 회의 제목
date: {date}             # 필수: YYYY-MM-DD
type: {enum}             # 필수: "manual" | "stt" | "hybrid"
attendees: {string[]}    # 선택: 참석자 리스트
summary: {string}        # 필수: 한 줄 요약 (50-100자)
---

# {title}

**일시**: {date}  
**참석자**: {attendees 또는 미기재}  
**자료유형**: {type}  
**한줄요약**: {summary}

---

**원문**: [raw.md](./raw.md)
```

#### 메타데이터 필드

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `title` | string | ✅ | 회의 제목 (30자 이내 권장) |
| `date` | date | ✅ | 개최 날짜 (YYYY-MM-DD) |
| `type` | enum | ✅ | `"manual"` (수동 메모), `"stt"` (자동 전사), `"hybrid"` (혼합) |
| `attendees` | string[] | - | 참석자 리스트 (가능한 만큼) |
| `summary` | string | ✅ | 한 줄 요약 (주요 결정/액션) |

#### 타입 정의

- **manual**: 사용자가 직접 작성한 메모
- **stt**: STT(Speech-to-Text) 자동 전사본
- **hybrid**: 수동 메모 + STT 하이브리드

### 3.2 주제 페이지 (`wiki/topics/슬러그/슬러그.md`)

```markdown
---
updated: {date}          # 필수: 마지막 갱신 YYYY-MM-DD
topics: {string[]}       # 선택: 관련 주제 태그
status: {enum}           # 선택: "active" | "on-hold" | "completed"
---

# {제목}

## 현황
{현재 상태 요약}

## 개요
{주제에 대한 일반적 설명}

## 의사결정 이력 (시간 역순)
### {날짜} — {결정 요약}
- {항목}
- 출처: [{회의명}]({상대경로})

## 액션아이템
- [x/☐] {내용} (담당자, ~기한) [{날짜}]({링크})

## 관련 페이지
- [{제목}]({상대경로}) — {관계 설명}
```

#### 주제 페이지 필수 구조

| 섹션 | 필수 | 설명 |
|---|---|---|
| `현황` | ✅ | 현재 상태 (1-2 문장) |
| `개요` | ✅ | 주제 설명 |
| `의사결정 이력` | ✅ | 시간 역순, 각 항목마다 출처 링크 |
| `액션아이템` | - | 미완료/완료 항목 리스트 |
| `관련 페이지` | - | 다른 주제로의 링크 |

#### 메타데이터 필드

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `updated` | date | ✅ | 마지막 갱신 날짜 (YYYY-MM-DD) |
| `topics` | string[] | - | 관련 주제 태그 (자유 형식) |
| `status` | enum | - | `"active"` (진행 중), `"on-hold"` (보류), `"completed"` (완료) |

### 3.3 롤업 페이지 (`wiki/decisions/decisions.md`, `wiki/action-items/action-items.md`)

#### decisions.md
```markdown
# 결정사항 전체

## {주제명}
- {결정 내용}
  - 출처: [{회의명}]({링크})
  - 관련 페이지: [{페이지}]({링크})
```

#### action-items.md
```markdown
# 오픈 액션아이템

## {회의명} ({날짜})
- [x/☐] {내용} (담당자, ~기한) — 출처: [{회의명}]({링크})

## 완료된 액션아이템
- [x] {내용} — 출처: [{회의명}]({링크})
```

## 4. 링크 규칙

### 4.1 링크 경로 깊이

기준점: `wiki/topics/슬러그/슬러그.md`

| 대상 | 경로 | 깊이 | 예시 |
|---|---|---|---|
| **raw 메타** | `../../../raw/` | 3단계 | `../../../raw/2026-08-10_회의/meta.md` |
| **형제 토픽** | `../` | 상대경로 | `../다른-슬러그/다른-슬러그.md` |
| **decisions** | `../../decisions/decisions.md` | 2단계 | (토픽에서) |

### 4.2 링크 포맷

- **마크다운 표준 링크만 사용**: `[텍스트](경로)`
- **Obsidian 위키링크 금지**: `[[슬러그]]` ❌
- **이유**: grep, 표준 마크다운 도구 호환성

### 4.3 역링크

- **필수 아님**: 모든 링크가 양방향일 필요 없음
- **권장**: 중요한 연결은 양방향 역링크 포함
- **예시**: A → B 링크 시, B의 "관련 페이지"에서 A 역링크

## 5. 컨텐츠 스타일

### 5.1 날짜 형식

| 항목 | 형식 | 예시 |
|---|---|---|
| 파일명/폴더명 | ISO 8601 | `2026-08-10` |
| frontmatter | ISO 8601 | `2026-08-10` |
| 본문 제목 | `YYYY-MM-DD` | `### 2026-08-10 회의 결정` |

### 5.2 리스트 형식

#### 의사결정 이력 (시간 역순, 최신 먼저)
```markdown
### 2026-08-10 — 결정 제목 (최신)
- **항목 1**: 내용
- **항목 2**: 내용
- 출처: [회의명](링크)

### 2026-08-03 — 이전 결정
- ...
```

#### 액션아이템
```markdown
- [☐] 내용 (담당자, ~기한) — 출처: [회의명](링크)
- [x] 완료됨 — 출처: [회의명](링크)
```

### 5.3 근거 투명성

- **모든 주요 내용에 출처 링크 필수**
  - "누가 언제 어디서 결정했는가"를 추적 가능
  - 출처 링크는 `[회의명](../../../raw/.../meta.md)` 형식

- **모순 처리**
  - 이전과 다른 결정: 지우지 말고 이력 남기기
  - 형식: "이전에는 X였으나, {날짜} 현재 Y로 변경 ([링크])"

## 6. 파일 생명주기

### 6.1 raw.md (원본)

| 단계 | 규칙 |
|---|---|
| **작성** | 회의 원문을 그대로 저장 |
| **저장 후** | **절대 수정 금지** (write-once) |
| **오타 수정** | ❌ raw.md 건드리지 말 것. 주제 페이지에 각주로 "역정정" 남기기 |
| **이력 추적** | meta.md로 충분 |

### 6.2 meta.md (메타카드)

| 단계 | 규칙 |
|---|---|
| **작성** | raw.md와 함께 작성 (필수) |
| **수정** | 필요시 가능 (메타정보는 변할 수 있음) |
| **참석자 누락** | 나중에 추가 가능 |

### 6.3 주제 페이지

| 단계 | 규칙 |
|---|---|
| **신규 생성** | `wiki/topics/슬러그/슬러그.md` 폴더 노트 형식, `index.md`에 등록 |
| **갱신** | 매 ingest마다 새 회의 정보 누적 |
| **updated 필드** | 마지막 갱신 날짜 갱신 필수 |
| **변경 이력** | 모순 시 삭제하지 말고 이력 남기기 |

### 6.4 롤업 페이지 (decisions, action-items)

| 단계 | 규칙 |
|---|---|
| **매 ingest마다** | 동시에 갱신 (SSOT 유지) |
| **decisions.md** | 신규 결정사항 추가 (주제 페이지에 먼저 기록) |
| **action-items.md** | 신규 액션 추가 및 완료 항목 갱신 |

## 7. 데이터 무결성

### 7.1 write-once 정책 (raw.md)

- **목표**: 원본 증거로서의 신뢰성 확보
- **규칙**: 저장 후 수정 금지
- **예외**: 없음 (오타도 그대로)
- **정정**: 주제 페이지에 각주로 "역정정" 처리

### 7.2 변경 이력 추적

```markdown
### 2026-08-10 — 정책 변경
- **이전**: 월 1회 정산
- **현재**: 고객사별 주기 상이 (재검토 필요)
- **사유**: 고객사 A의 주 1회 정산 요청
- 출처: [2026-06-11 회의](링크)
```

### 7.3 상호 참조 일관성

- **index.md**: 모든 주제 페이지 링크 필수
- **주제 페이지**: 모든 회의 링크 필수 (meta.md 경유)
- **결정사항**: decisions.md와 주제 페이지에 동시 기록
- **액션아이템**: action-items.md와 주제 페이지에 동시 기록

## 8. 검증 규칙 (Lint)

### 8.1 Lint 체크리스트

| 항목 | 기준 | 기준값 |
|---|---|---|
| **고아 페이지** | wiki/topics 내 파일이 index.md에 링크 | 0건 |
| **끊어진 링크** | 상대경로 링크가 실제 파일을 가리킴 | 0건 |
| **모순** | 시점 구분 없이 충돌하는 서술 | 0건 |
| **역링크 누락** | 중요 연결은 양방향 | 적절함 |
| **오래진 액션** | 4주 이상 갱신 안 된 항목 | 플래그 |
| **index.md 누락** | wiki/topics 모든 파일 등록 | 0건 |

### 8.2 Lint 빈도

- **신규 ingest 후**: 매번 링크 유효성 검증
- **주기적**: 월 1회 전체 lint 실행 권장

## 10. 용어 정의

| 용어 | 정의 |
|---|---|
| **SSOT** | Single Source of Truth. 각 정보는 정확히 한 곳에만 정의되고, 다른 곳은 링크로 참조 |
| **raw.md** | 원본 회의 기록. 손수정하지 않는 근거 자료 |
| **주제 페이지** | 같은 주제의 정보를 여러 회의에서 누적한 페이지 |
| **롤업** | 여러 주제 페이지에서 정보를 모아 한곳에 집약 (decisions.md, action-items.md) |
| **폴더 노트** | 폴더와 같은 이름의 md 파일이 폴더의 진입점 역할 |
| **메타카드** | 원문의 가벼운 요약 (제목, 날짜, 참석자, 한줄요약) |
