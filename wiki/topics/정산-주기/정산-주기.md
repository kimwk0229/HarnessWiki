# 정산-주기 (Settlement Cycle)

고객사 정산 주기 정책 수립.

## 현황

**2026-06-11 기준 (최신):**
- 정책: 월 1회 (말일 기준) — 재검토 중
- 상태: 보류 (고객사 A 주 1회 정산 요청으로 재논의 필요)
- 고려사항: 고객사별 요청 다양성, 운영 부담 vs 고객 만족도

## 개요

고객사에서 정산 주기 문의가 들어오면서 정책 수립 필요.
- 운영 부담과 고객 만족도 균형
- 자주 돌리면 운영 복잡도 증가
- 향후 고객 요청 증가 시 유연하게 조정

## 결정사항

### 2026-06-11 (최신)
- **결론 보류** — 다음 회의에서 재논의
  - 이유: 고객사 A의 주 1회 정산 요청 vs 개발팀 운영 부담 (자동화 미완료 상태에서 주 1회 = 부담 4배)
  - 미정: 고객사마다 다르게 갈 수 있는지 정책 검토 필요
  - 강태우: 계약 규모가 크므로 요청 무시하기 어려움

## 고려사항 & 이슈

### 고객사별 정산 주기 차등 정책
- **설명**: 고객사 A의 주 1회 정산 요청 → 기존 월 1회 정책과 충돌
- **현재 상태**: 고객사별로 다르게 갈 수 있는지 검토 필요 (2026-06-11 기준)
- **필요한 조치**: 자동화 여부 검토 후 고객사별 정책 수립 검토
  - 자동화 완료 시 유연한 정책 가능
  - 미자동화 상태에서는 운영 부담 고려 필요 (주 1회 = 부담 4배)

### 미정 항목
- 재무팀 정산 프로세스 확인 필요 (담당자 미정)
- 고객사별 정산 주기 차등 정책 수립 검토 필요
