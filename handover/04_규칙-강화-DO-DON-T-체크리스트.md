HarnessWiki의 **CLAUDE.md** 스키마 문서에 명확한 규칙과 체크리스트를 추가했습니다.
폴더 노트 구조 전환(03번 handover)을 완료한 후, 앞으로 새 회의를 수집할 때

## 추가/개선된 섹션

### 1. **링크 규칙 (경로 깊이)** — 새로 추가

주제 페이지 위치(`wiki/topics/슬러그/슬러그.md`) 기준:

| 링크 유형 | 올바른 경로 | 규칙 |
|---|---|---|
| raw 참조 | `../../../raw/YYYY-MM-DD_슬러그/meta.md` | 항상 3단계 |
| 형제 토픽 | `../다른-슬러그/다른-슬러그.md` | 같은 topics/ 내 |
| 결정 롤업 | `../topics/슬러그/슬러그.md` | decisions.md에서 출발 |
| 액션 롤업 | `../../raw/YYYY-MM-DD_슬러그/meta.md` | action-items.md에서 출발 |

**핵심**: 링크 깊이를 혼용하지 말 것. raw는 항상 3단계, 형제는 상대경로 통일.

### 2. **오퍼레이션 1: 수집 (Ingest)** — 상세화

9단계 프로세스 각 단계에 `**rule:**` 마크로 추가:

1. 메타정보 확인
2. 원본 저장 → **rule**: raw.md 저장 후 절대 수정 금지 (write-once)
3. 주제 페이지 검색 → **rule**: 새 토픽은 폴더 노트 형식만 허용
4. 정보 누적 → **rule**: 모순 시 변경이력 남기기, 근거 링크 필수
5. 결정사항 롤업 → **rule**: decisions.md 필수 갱신 (SSOT)
6. 액션아이템 롤업 → **rule**: action-items.md 필수 갱신 (SSOT)
7. **링크 유효성 검증** (신규) → **rule**: 깨진 링크로 완료 금지
8. 로그 업데이트
9. 사용자 보고

### 3. **Ingest 체크리스트** — 새로 추가

ingest 완료 전 반드시 확인:

```
- [ ] raw.md 저장 완료 (수정 금지, write-once 정책 준수)
- [ ] meta.md 작성 완료 (제목/날짜/자료유형/한 줄 요약 포함)
- [ ] 주제 페이지 신규 생성 시 폴더 노트 구조 준수 (wiki/topics/슬러그/슬러그.md)
- [ ] 모든 링크 경로 검증 (raw: ../../../raw/, 형제 토픽: ../슬러그/슬러그.md)
- [ ] 신규 토픽이면 index.md에 등록
- [ ] wiki/decisions/decisions.md 동시 갱신
- [ ] wiki/action-items/action-items.md 동시 갱신
- [ ] log.md에 [INGEST] 항목 추가
- [ ] 생성/갱신된 파일 목록을 사용자에게 보고
```

### 4. **규칙 (DO/DON'T)** — 새로운 섹션

#### ✅ 꼭 해야 할 규칙 (4분류 14항)

**구조**
- raw.md는 저장 후 절대 수정 금지 (write-once). 오타도 건드리지 말 것.
- 신규 토픽 페이지는 반드시 폴더 노트 형식: `wiki/topics/슬러그/슬러그.md`
- 신규 토픽 생성 후 즉시 `index.md`에 등록

**링크**
- raw 참조: 항상 `../../../raw/YYYY-MM-DD_슬러그/meta.md` (3단계, 일관성)
- 형제 토픽: 항상 `../슬러그/슬러그.md` (상대경로, 일관성)
- ingest 완료 전 모든 신규 링크 검증 (깨진 링크 허용 안 함)

**업데이트**
- ingest 후 반드시 `wiki/decisions/decisions.md` 갱신
- ingest 후 반드시 `wiki/action-items/action-items.md` 갱신
- 기존 내용과 모순되면, 지우지 말고 변경 이력 남기기: "2026-08-10 변경: 이전 X → 현재 Y ([링크])"
- `log.md`에 `[INGEST]` 항목 추가

**투명성**
- 주제 페이지에 근거 링크 필수 (어느 회의에서 나온 정보인지)
- meta.md는 회의 원문의 가벼운 카드 역할 (요약, 참석자, 일시 등)

#### ❌ 절대 하지 말 규칙 (5분류 11항)

**구조**
- `wiki/topics/슬러그.md` 형식 사용 금지 (평면 구조, 구 형식)
- 같은 주제에 여러 슬러그 페이지 생성 금지 (중복 주제 페이지)

**링크**
- raw 링크를 `../../raw/`, `../../../../raw/` 등으로 섞어 쓰기 금지
- Obsidian `[[위키링크]]` 사용 금지 (마크다운 표준 링크만 사용)

**raw.md**
- raw.md 저장 후 수정 금지 (오타 포함)
- 정정이 필요하면 주제 페이지에 각주로 "역정정" 남기기

**업데이트**
- ingest 후 decisions.md, action-items.md 갱신 누락 (SSOT 깨짐)
- 신규 토픽 생성했는데 index.md에 등록 안 함 (고아 페이지 생성)

**동시성**
- 같은 토픽 페이지를 사용자와 LLM이 동시 편집 금지 (merge 충돌)
- ingest 진행 중 그 주제 페이지 사용자 편집 금지

#### 💡 선택적이지만 권장 (NICE-TO-HAVE)

- frontmatter에 `updated`, `topics`, `status` 필드 (최소 updated 필드)
- 주제 페이지마다 "관련 토픽" 섹션 (다른 토픽으로의 양방향 역링크)
- raw.md에 최소 섹션 구조 (### 논의 내용, ### 결정사항, ### 액션아이템)

### 5. **스타일 가이드** — 강화

**링크**
- Obsidian `[[위키링크]]` 문법 **절대 사용 금지** (마크다운 표준 링크만)
- 이유: grep, 일반 마크다운 도구와의 호환성

**frontmatter** (선택적 권장)
```yaml
---
updated: 2026-08-10
topics: [주제1, 주제2]
status: active
---
```

**raw.md 포맷** (완전 자유형식, 하지만 권장 구조)
- `### 논의 내용` / `### 핵심 포인트`
- `### 결정사항`
- `### 액션아이템` / `### 할 일`

## 변경 이유

### 왜 이런 규칙들을 추가했는가?

1. **폴더 노트 구조 확정 후** (03번 handover)
   - 새 구조에 맞는 명확한 링크 깊이 규칙이 필수
   - 깊이를 혼용하면 grep이 깨짐

2. **SSOT(Single Source of Truth) 유지**
   - decisions.md, action-items.md 갱신 누락이 가장 흔한 실수
   - 체크리스트로 강제화

3. **투명성과 감사추적성**
   - raw.md write-once 정책 재확인 (원본 무결성)
   - 변경이력 형식 명확화

4. **동시성 주의**
   - 사용자와 LLM의 동시 편집 시 merge 충돌 위험
   - 명시적 경고 추가

## 요점 정리

**이 작업이 해결한 문제**
- ingest 시 누락되기 쉬운 항목들을 체크리스트로 강제화
- 링크 깊이 혼용으로 인한 grep 호환성 문제 방지
- SSOT 깨짐 (decisions/action-items 갱신 누락) 방지
- 동시 편집 충돌 예방

**앞으로의 ingest 프로세스**
1. 회의 메모 받음
2. raw/meta.md 저장
3. 9항 체크리스트 확인하며 ingest 진행
4. DO/DON'T 규칙 준수 확인
5. 링크 깊이 검증 (3단계 raw, 상대경로 형제)
6. decisions/action-items 동시 갱신
7. log.md 기록
8. 사용자 보고
