## 완성된 구성

### 1. **기계 검증 (Lint)** — `scripts/lint.ts`

**역할**: Frontmatter YAML, 파일 구조, 슬러그, 링크 자동 검증

**검증 항목**:
- ✅ Frontmatter YAML 유효성 (raw.md, meta.md, 토픽 페이지)
- ✅ 파일 구조 규칙 (경로, 폴더명, 파일명)
- ✅ 슬러그 규칙 (kebab-case, 한글 허용)
- ✅ 링크 유효성 (깨진 링크, 경로 깊이)

**실행**:
```bash
npm run lint
```

**출력**: `[ERROR]`, `[WARN]`, `[INFO]`, `[SUMMARY]` 섹션

**종료 코드**:
- `0`: 성공 (오류 없음)
- `1`: 오류 발생

---

### 2. **컨텐츠 검증 (LLM)** — `.claude/skills/content-review/`

**역할**: Claude가 회의 원본과 위키 반영 내용을 비교

**검증 항목** (5가지):
1. **일치도 (Content Alignment)**: 회의 내용과 위키 반영 일치도
2. **할루시네이션 (No Hallucination)**: 회의에 없는 정보 추가 여부
3. **누락 (Completeness)**: 중요 내용 누락 여부
4. **액션 추적 (Action Lifecycle)**: 액션 상태 변화 추적
5. **메타정보/링크 (Meta & Links)**: 메타데이터, 링크 검증

**실행**:
```bash
/content-review 2026-06-11              # 기본
/content-review 2026-06-11 --verbose    # 상세 분석
/content-review 2026-06-11 --focus=슬러그1,슬러그2  # 특정 토픽만
/content-review 2026-06-11 --strict     # 엄격 모드
```

**판정**:
- ✅ **APPROVED**: 5/5 항목 PASS → 바로 커밋 가능
- ⚠️ **REVIEW NEEDED**: 1개 이상 REVIEW, FAIL 없음 → 수정 후 재검증
- ❌ **FAILED**: 1개 이상 FAIL → 재ingest 또는 심각한 수정 필요

---

### 3. **통합 검증** — `.claude/skills/validate-wiki/`

**역할**: 기계 검증 + 컨텐츠 검증을 순차 실행, 통합 리포트 생성

**실행**:
```bash
/validate-wiki 2026-06-11                           # 기본
/validate-wiki 2026-06-11 --save-report             # 파일 저장
/validate-wiki 2026-06-11 --detailed                # 상세 내용
/validate-wiki 2026-06-11 --save-report --detailed  # 상세 저장
```

**출력 형식**:
```markdown
# HarnessWiki 검증 리포트
## 회의: [회의명]
## 날짜: YYYY-MM-DD
## 검증 일시: YYYY-MM-DD HH:MM:SS

---

## 1️⃣ 기계 검증 (Lint) 결과
**상태**: ✅ PASS / ⚠️ WARNING / ❌ FAIL

### 오류 (N건) / 경고 (N건) / 정보 (N건)

---

## 2️⃣ 컨텐츠 검증 (LLM Review) 결과
**상태**: ✅ APPROVED / ⚠️ REVIEW NEEDED / ❌ FAILED

### 검증 항목별 결과
1. 일치도: ✅ PASS
2. 할루시네이션: ✅ PASS
3. 누락: ✅ PASS
4. 액션 추적: ✅ PASS
5. 메타정보/링크: ✅ PASS

### 발견 사항
[있으면 기술, 없으면 "없음"]

---

## 📊 최종 판정
✅ 모든 검증 통과 / ⚠️ 검토 필요 / ❌ 검증 실패
```

---

## 사용 워크플로우

### 회의 수집 완료 후 검증 실행

```bash
# 1단계: 회의 수집
/ingest

# 2단계: 통합 검증 (기계 + 컨텐츠)
/validate-wiki YYYY-MM-DD

# 3단계: 결과 확인
# - ✅ APPROVED → git commit 진행
# - ⚠️ REVIEW NEEDED → 지적사항 수정 후 재검증
# - ❌ FAILED → 재ingest 또는 심각한 수정

# 4단계: 커밋
git commit -m "[INGEST] YYYY-MM-DD 회의 적재 완료"
```

```

```

```
→ 해결: raw.md 재검토 및 재ingest 필요
```
