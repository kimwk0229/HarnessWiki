**작성일**: 2026-08-10  
**상태**: 부트스트랩 완료 → 다음 단계 대기 중

## 배경 및 목적

사용자는 Andrej Karpathy의 ["LLM Wiki"](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 패턴을 참고하여 회의록을 위한 SSOT(Single Source of Truth) 위키 시스템을 구축하려고 한다.

**핵심 아이디어**: 매번 RAG로 재검색하는 대신, LLM이 지속적으로 마크다운 위키를 구축·유지보수하여 지식이 재발견되지 않고 누적되는 구조.

**기대 효과**:
- 회의 정보가 주제별로 체계화되어 나중에 쉽게 찾고 합성할 수 있다.
- 결정사항과 액션아이템이 자동으로 롤업되어 "지금 뭐가 열려있는가"를 언제든 확인할 수 있다.
- 회의가 쌓일수록 위키 지식의 진가가 드러난다.

## 확정된 설계 결정 4가지

| 항목 | 결정 | 배경 |
|------|------|------|
| **실행 형태** | Claude Code 프로젝트 | 별도 앱이나 데이터베이스 없이, Claude Code 세션에서 대화하며 회의록을 수집/쿼리/린트한다. |
| **입력 형식** | 수동 메모 + STT 전사 혼합 | 회의마다 메모 방식이 달라질 수 있으므로, 둘 다 지원한다. |
| **조직 기준** | 주제/토픽별 | 회의 자체가 위키의 1차 콘텐츠가 아니라, 여러 회의의 정보가 같은 주제 페이지에 누적된다. |
| **구조화 수준** | 가볍게(자유 형식) | 참석자/결정/액션아이템에 엄격한 필드를 강제하지 않고, 자유로운 마크다운 문장/불릿으로 자연스럽게 표현한다. |

## 디렉토리 구조 및 파일 역할

```
D:\HarnessWiki\
├── CLAUDE.md                      # 스키마 정의 (수집/쿼리/린트 규칙, 디렉토리 규칙)
├── index.md                       # 위키 페이지 카탈로그 + 롤업 페이지 링크
├── log.md                         # 시간순 변경 이력 ([INGEST]/[QUERY]/[LINT] 태그)
├── _templates/                    # 템플릿 모음 (린트 제외)
│   ├── meeting-raw.template.md    # 회의 원문 저장 안내
│   ├── meeting-meta.template.md   # 회의 메타카드 템플릿 (제목/일시/참석자/링크)
│   └── topic-page.template.md     # 주제 페이지 템플릿
├── sources/                       # 원본 계층 (불변)
│   └── (YYYY-MM-DD_슬러그 폴더들, 첫 ingest 시 생성)
├── wiki/
│   ├── decisions.md               # 결정사항 롤업 (자동 합성)
│   ├── action-items.md            # 액션아이템 롤업 (자동 합성)
│   └── topics/                    # 주제 페이지들 (첫 ingest 시 생성)
├── handover/                      # 이 파일과 향후 핸드오버 문서들
└── .claude/                       # Claude Code 설정 (제외)
```

| 파일/폴더 | 역할 | 수정 정책 |
|---------|------|---------|
| `CLAUDE.md` | 스키마 정의: 3계층 구조, 수집/쿼리/린트 절차, 스타일 가이드 | 규칙 변경 시만 수정 |
| `index.md` | 위키 전체 카탈로그 + 롤업 페이지 링크. 신규 주제 페이지 생성마다 여기 추가 | ingest 절차의 부산물로 자동 갱신 |
| `log.md` | ingest/query/lint 작업 기록. 최신이 위(역순). 날짜별 섹션으로 정리. | ingest 절차의 부산물로 자동 갱신 |
| `_templates/` | 회의 메타카드, 원문 저장, 주제 페이지의 템플릿 | 필요시 개선 가능 |
| `sources/YYYY-MM-DD_슬러그/raw.md` | 회의 원문 그대로(절대 수정 금지) | Write-once 정책 |
| `sources/YYYY-MM-DD_슬러그/meta.md` | 회의 메타카드(제목/일시/참석자/유형/요약) | ingest에서 한 번 작성 후 고정 |
| `wiki/topics/*.md` | 주제별 누적 정보(여러 회의 병합) | ingest마다 정보 추가, 모순 시 이력 기록 |
| `wiki/decisions.md` | 모든 주제에서 나온 결정사항 롤업 | ingest 절차 중 자동 갱신 |
| `wiki/action-items.md` | 미완료 액션아이템 체크리스트 | ingest 절차 중 자동 추가 |

## 3가지 오퍼레이션

### 1. 수집 (Ingest)
새 회의록이 들어왔을 때의 처리 순서:
1. 메타정보 확인(날짜/제목/참석자/자료유형)
2. `sources/YYYY-MM-DD_슬러그/raw.md`에 원문 저장(절대 수정 금지)
3. `meta.md` 작성
4. 관련 주제 페이지 검색(grep) → 없으면 신규 생성
5. 각 주제 페이지에 정보 누적(모순 시 "이전 X → 현재 Y" 형태로 이력 남김)
6. 결정사항은 `wiki/decisions.md`에도 반영
7. 액션아이템은 `wiki/action-items.md`에 체크박스로 추가
8. 신규 페이지는 `index.md`에 등록
9. `log.md`에 `[INGEST]` 기록
10. 사용자에게 처리 결과 보고

### 2. 쿼리 (Query)
사용자 질문에 답할 때:
1. `index.md` 또는 grep으로 관련 페이지 검색
2. 위키 정보로 답변(없으면 "위키에 없음"을 명시하고 `sources/` 직접 검색 제안)
3. 재사용 가치 있는 새로운 통합이면, 저장 여부를 사용자에게 확인 후 `log.md`에 `[QUERY]` 기록
4. 답변에 근거 링크 포함

### 3. 린트 (Lint)
주기적으로 위키 상태를 검사:
- 고아 페이지(링크 없는 `wiki/topics/` 파일)
- 끊어진 링크(실제로 없는 파일을 가리키는 링크)
- 시점 구분 없는 모순(같은 주제에 "A는 X"와 "A는 Y"가 동시에 있는 경우)
- 역링크 누락(A가 B를 링크하는데 B에 A 역링크가 없는 경우)
- 4주 이상 방치된 액션아이템
- `index.md`에 없는 주제 페이지

발견 사항을 보고 후 사용자 승인받아 수정, `log.md`에 `[LINT]` 기록.

❌ **아직 없는 것**:
- 실제 회의록(sources 폴더가 비어있음)
- 실제 주제 페이지(wiki/topics 폴더가 비어있음)
- 롤업 페이지의 실제 콘텐츠

## 다음 단계

**마일스톤 2**: 첫 실제 회의록 투입 및 ingest 검증
1. 사용자로부터 회의록(수동 메모 또는 STT 전사본) 1개 받기
2. ingest 절차 실행: `sources/` → `meta.md` 작성 → 첫 주제 페이지 생성 → 롤업 페이지 갱신
3. Query 검증: "A 주제에 대해 뭐가 결정됐어?" 같은 간단한 쿼리로 위키 기반 답변이 근거 링크와 함께 나오는지 확인
4. Lint 검증: "린트해줘" 실행해 고아 페이지/누락 링크 점검 동작 확인

이 과정이 CLAUDE.md 규칙을 따르고 자연스럽게 흘러가면, 하네스가 정상 작동하는 것으로 판단.

**마일스톤 3 이후** (추후 핸드오버 문서 `02_`, `03_` 참조):
- 여러 회의 축적 시 주제별 누적/합성 패턴 검증
- 필요 시 스키마 개선(예: 역할 담당별 페이지, 참석자 로스터 추가 등)
